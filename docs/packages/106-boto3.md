# boto3 — AWS SDK for Python

> boto3 is the official AWS SDK — talk to S3, DynamoDB, SQS, and every other
> AWS service from Python. Clients are thin wrappers over the AWS API;
> resources add a friendlier, more Pythonic layer on top of some of them.

## Install and configure

```bash
python -m pip install boto3
```

boto3 does not take credentials as constructor arguments in real code.
Configure them once, outside your source tree:

```bash
aws configure   # writes ~/.aws/credentials and ~/.aws/config
# or export AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_DEFAULT_REGION
```

```python
import boto3

s3 = boto3.client("s3")
for bucket in s3.list_buckets()["Buckets"]:
    print(bucket["Name"])
```

boto3 picks up credentials automatically from the environment, `~/.aws/`,
or an attached IAM role — never hardcode a key or secret in source code.

## Upload and download from S3

```python
import boto3

s3 = boto3.client("s3")
s3.upload_file("report.csv", "my-bucket", "reports/report.csv")
s3.download_file("my-bucket", "reports/report.csv", "downloaded.csv")
```

For anything larger than a few hundred MB, boto3's `upload_file` already
handles multipart uploads for you — you do not need to chunk it manually.

## read and write DynamoDB items

```python
import boto3

table = boto3.resource("dynamodb").Table("Devices")
table.put_item(Item={"device_id": "line1-sensor", "status": "ok"})
resp = table.get_item(Key={"device_id": "line1-sensor"})
print(resp["Item"])
```

The `resource` API (used here) is higher-level than `client` — it maps
DynamoDB's types to native Python `dict`/`list`/`Decimal` values for you.

## error handling

```python
import boto3
from botocore.exceptions import ClientError

s3 = boto3.client("s3")
try:
    s3.download_file("my-bucket", "missing.csv", "out.csv")
except ClientError as e:
    if e.response["Error"]["Code"] == "404":
        print("object does not exist")
    else:
        raise
```

AWS errors surface as `ClientError` with a structured `.response["Error"]`
dict — check `Code` rather than parsing the exception message.

## Least-privilege and cost safety

Grant the running credentials only the specific actions and resources they
need (e.g. `s3:GetObject` on one bucket, not `s3:*` on all of them). Set a
billing alarm before running anything that provisions metered resources
(EC2, RDS, etc.), and tear down test infrastructure when you are done.
